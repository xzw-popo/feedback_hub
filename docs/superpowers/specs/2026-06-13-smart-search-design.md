# 智能搜索设计文档

> 日期：2026-06-13
> 状态：已确认

## 1. 概述

为反馈列表页新增智能搜索能力，包含两个并列的搜索入口和一层 AI 精筛：

- **关键词构建器**：分组式关键词 + AND/OR 逻辑 + 排除词，面向精确搜索
- **AI 智能搜索**：自然语言输入 → LLM 翻译为正则表达式 → SQL REGEXP 查询，面向意图搜索
- **AI 精筛**：对初筛结果逐条 LLM 评分，附加"AI 相关性"列，支持排序

现有元数据筛选（L1/L2/severity/时间范围）保留为独立筛选层，与搜索条件 AND 组合。

## 2. 整体架构

```
┌─────────────────────────────────────────────────────┐
│                    列表页 (List.vue)                  │
│                                                       │
│  ┌─ 元数据筛选层 ─────────────────────────────────┐  │
│  │  时间范围 │ L1 │ L2 │ severity          [筛选]  │  │
│  └─────────────────────────────────────────────────┘  │
│                                                       │
│  ┌─ AI 智能搜索 ──────────────────────────────────┐  │
│  │  [ 用自然语言描述你想查找的反馈...        ] [搜索]│  │
│  └─────────────────────────────────────────────────┘  │
│  ─ ─ ─ 或 手动构建关键词 ─ ─ ─                       │
│  ┌─ 关键词构建器 ─────────────────────────────────┐  │
│  │  组1(AND): [快捷键] [语音]   组2(OR): [声控]    │  │
│  │  排除: [广告]              [+添加分组] [搜索]    │  │
│  └─────────────────────────────────────────────────┘  │
│                                                       │
│  ┌─ 结果表格 ─────────────────────────────────────┐  │
│  │ 时间 │ 反馈 │ L1 │ L2 │ sev │ 平台 │ AI相关性 │  │
│  │      │      │    │    │     │      │ ⭐⭐⭐    │  │
│  └─────────────────────────────────────────────────┘  │
│                              [✨ AI 精筛]              │
└───────────────────────────────────────────────────────┘
```

**数据流**：

1. 用户选择输入方式（AI 或关键词），可选配合元数据筛选
2. 后端执行 SQL 查询返回初筛结果
3. 用户点击"AI 精筛"按钮
4. 后端并发调用 LLM 逐批评分，前端通过 SSE 流式更新"AI 相关性"列
5. 用户按相关性列排序查看

**元数据筛选条件**始终作为 WHERE 子句 AND 到任何搜索查询中。

## 3. 后端 API

### 3.1 `POST /api/smart-search` — AI 智能搜索（粗筛）

请求：

```json
{
  "query": "用户对语音输入快捷键的意见",
  "filters": {
    "from": "2026-06-01",
    "to": "2026-06-12",
    "L1": "A.Bug",
    "L2": null,
    "severity": null
  },
  "limit": 200,
  "offset": 0
}
```

响应（与现有 `/api/conversations` 格式一致）：

```json
{
  "total": 47,
  "items": [...],
  "debug": {
    "regex_patterns": ["语音.*(输入|打字|识别)|声控|听写", "快捷键|快捷方式|热键|shortcut"],
    "logic": "AND"
  }
}
```

`debug` 字段不展示给用户，仅用于后端日志排查。

**后端逻辑**：

1. 将用户自然语言 + L1/L2 标签体系参考拼成 prompt
2. 一次 LLM 调用，要求输出 1-N 个正则表达式 + 组合逻辑（AND/OR）
3. 校验正则合法性（长度 ≤ 200 字符，禁止回溯型模式）
4. 拼接 SQL REGEXP 查询 + 元数据筛选 WHERE 条件
5. 无效正则回退为简单 LIKE 查询（拆出关键词）

### 3.2 `POST /api/keyword-search` — 关键词构建器搜索

请求：

```json
{
  "groups": [
    { "keywords": ["快捷键", "语音"], "logic": "AND" },
    { "keywords": ["声控", "语音输入"], "logic": "OR" }
  ],
  "excludes": ["广告"],
  "filters": { ... },
  "limit": 200,
  "offset": 0
}
```

响应格式同 `/api/conversations`。

**SQL 翻译规则**：

```sql
WHERE (
    (text REGEXP '快捷键' AND text REGEXP '语音')
    OR
    (text REGEXP '声控' OR text REGEXP '语音输入')
  )
  AND text NOT REGEXP '广告'
  AND -- 元数据筛选条件
```

### 3.3 `POST /api/fine-filter` — AI 精筛

请求：

```json
{
  "query": "用户对语音输入快捷键的意见",
  "conversation_ids": ["conv_001", "conv_002", ...],
  "batch_size": 10
}
```

响应：SSE 流式，每批完成后推送：

```
data: {"batch": [{"id": "conv_001", "score": 3}, {"id": "conv_002", "score": 1}, ...]}
data: {"batch": [...]}
data: {"done": true, "total_processed": 47}
```

评分：1=低相关, 2=中相关, 3=高相关。不持久化，每次实时计算。

### 3.4 现有端点

- `GET /api/conversations` 保持不变
- `GET /api/export.csv` 后续可扩展支持 smart-search / keyword-search 参数

## 4. LLM 集成

### 4.1 配置

环境变量：

| 变量 | 说明 | 示例 |
|------|------|------|
| `LLM_API_URL` | LLM API 端点 | `https://api.example.com/v1/chat/completions` |
| `LLM_API_KEY` | API 密钥 | `sk-xxx` |
| `LLM_MODEL` | 模型名称 | `gpt-4o-mini` |

### 4.2 粗筛 Prompt 设计

```
你是一个搜索条件生成器。用户想查找用户反馈，请根据他们的意图生成正则表达式。

## 用户的反馈标签体系参考
L1 分类：A.Bug, B.建议, C.咨询, D.情绪, E.无效
L2 标签：输入核心, 语音, 符号表情, 皮肤, 词库, 账号, 键盘交互, 安装更新, 性能, 权限隐私, 广告活动, 其他

## 用户意图
{query}

## 输出格式
返回 JSON：
{
  "patterns": ["正则1", "正则2"],
  "logic": "AND" 或 "OR"
}

要求：
- 正则要覆盖用户意图的各种表述变体（同义词、近义词、口语化表达）
- 每个正则长度不超过 200 字符
- 不要使用回溯型模式
- logic 表示多个正则之间的关系
```

### 4.3 精筛 Prompt 设计

```
你是一个反馈相关性判断器。用户想查找特定类型的用户反馈，请判断每条反馈与用户意图的相关程度。

## 用户意图
{query}

## 待判断的反馈
{numbered_feedback_list}

## 输出格式
对每条反馈返回 1-3 的评分：
- 3：高相关，直接匹配用户意图
- 2：中相关，部分匹配或间接相关
- 1：低相关，基本不匹配

返回 JSON 数组：
[{"id": 1, "score": 3, "reason": "简短理由"}, ...]
```

## 5. 前端组件

### 5.1 组件树

```
views/List.vue
├── FilterBar.vue              ← 现有，保留（元数据筛选层）
├── SmartSearch.vue            ← 新增：AI 智能搜索区
├── KeywordBuilder.vue         ← 新增：关键词构建器
│   ├── KeywordGroup.vue       ← 新增：单个关键词组
│   └── ExcludeSection.vue     ← 新增：排除词区域
├── ConversationTable.vue      ← 现有，修改：新增 AI 相关性列
└── FineFilterButton.vue       ← 新增：精筛触发按钮
```

### 5.2 SmartSearch.vue

- 文本输入框 + "AI 搜索"按钮
- Placeholder：`"用自然语言描述你想查找的反馈..."`
- 搜索中状态：输入框下方显示 `"AI 正在理解你的意图..."`
- 搜索完成后 loading 消失，结果填充到表格

### 5.3 KeywordBuilder.vue

- 初始状态：一个默认组（组 1, AND），输入框提示 `"+ 关键词"`
- 关键词回车后变为绿色芯片，点 ✕ 删除
- 组标签右侧 AND/OR 切换
- 组间显示 `OR` 分隔线
- 底部 `+ 添加分组` 按钮
- 排除区域固定在最下方，独立于分组，红色芯片
- 右侧"搜索"按钮

### 5.4 KeywordGroup.vue

```
┌─ 组 1 · [AND ▾] ─────────────────────────┐
│  [快捷键 ✕] [语音 ✕]  [输入关键词...     ] │
└────────────────────────────────────────────┘
```

- 组头：组名 + 逻辑切换下拉（AND/OR）
- 组 1 不可删除，后续组右上角有 ✕

### 5.5 ConversationTable.vue 修改

新增"AI 相关性"列：

| 状态 | 显示 |
|------|------|
| 未精筛 | — |
| 精筛进行中（已评分） | ⭐⭐⭐(绿) / ⭐⭐(橙) / ⭐(灰) |
| 精筛进行中（未评分） | loading 图标 |
| 精筛完成 | 评分固定，列头可点击排序 |

### 5.6 FineFilterButton.vue

| 状态 | 文案 |
|------|------|
| 有搜索结果，未精筛 | `✨ AI 精筛` |
| 精筛进行中 | `✨ 精筛中... 23/47` |
| 精筛完成 | `✨ 重新精筛` |

精筛的意图来源：
- AI 搜索模式：自动取输入框内容
- 关键词搜索模式：由关键词组合生成描述（如"包含'快捷键'和'语音'，排除'广告'"）

### 5.7 搜索模式互斥

- 同一时刻只能激活一种搜索模式的结果
- 用 AI 搜索时，关键词构建器搜索按钮置灰；反之亦然
- 切换搜索模式时清空当前结果和精筛评分
- 元数据筛选不受搜索模式切换影响
- 两种搜索都为空时，等同现有列表浏览（按时间倒序），精筛按钮隐藏

## 6. 精筛性能参数

| 参数 | 值 | 说明 |
|------|------|------|
| 单次精筛上限 | 500 条 | 超过提示缩小范围 |
| 每批条数 | 10 条 | 单次 LLM 调用评估 10 条 |
| 最大并发 LLM 调用 | 50 | 同时处理 500 条，API 已验证 128 并发稳定 |
| 单批超时 | 30s | |
| 整体超时 | 3 分钟 | |
| 取消支持 | 是 | 已有评分保留 |

## 7. 异常处理

| 场景 | 处理 |
|------|------|
| LLM 返回无效正则 | 校验正则合法性，无效则回退为 LIKE 查询，日志记录 |
| LLM API 不可用 | 返回错误提示"AI 服务暂时不可用，请尝试关键词搜索"，不阻塞关键词构建器 |
| 正则性能风险 | 限制长度 ≤ 200 字符，禁止回溯型模式 |
| 精筛结果过大 | > 500 条时提示缩小范围 |
| 精筛超时 | 3 分钟超时，返回已评分部分 |
| SSE 连接断开 | 前端自动重试一次，显示已完成的部分评分 |
