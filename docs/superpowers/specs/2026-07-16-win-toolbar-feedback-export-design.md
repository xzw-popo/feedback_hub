# Win 工具栏专题反馈清单设计

## 目标

生成一份一次性的 Excel 反馈清单，覆盖 2026-01-16 至 2026-07-16 执行时点的 Win 端反馈，只收录以下两个问题：

1. 工具栏位置错乱，例如工具栏跑到左下角、右上角、其他屏幕或无法保持用户设置的位置。
2. 游戏处于全屏状态时，工具栏不会自动隐藏、持续置顶或遮挡游戏画面。

本次不建设看板固定专题，不修改通用标签体系，也不把专题数据写回远端生产库。

## 数据现状

- 远端 `feedback_hub/data/feedback.db` 是最新数据源，已更新到 2026-07-16，现有数据最早为 2026-04-21。
- 本地同名数据库只更新到 2026-06-24，不能作为本次专题的基准库。
- 要满足完整半年口径，需要补拉 2026-01-16 00:00:00 至 2026-04-21 00:00:00 的历史原始反馈。
- `pull` 和 `tag` 是两个独立步骤。日常同步脚本会依次调用两者，但本次历史补拉只执行原始数据拉取，不执行通用打标。

## 数据副本与补拉

1. 在远端使用 SQLite 一致性备份生成只读快照，再下载到本地专题目录。
2. 所有专题数据库、原始响应、候选文件和导出文件放在 `feedback_hub/data/` 下，不进入 Git。
3. 在本地专题数据库中按自然日补拉缺失区间，逐日记录成功、失败、返回量和新增量。
4. 拉取过程可断点续跑；失败日期重试后仍失败时停止交付，并明确列出缺口，不把不完整数据描述为“完整半年”。
5. 本地补拉和筛选期间不覆盖本地正式 `feedback.db`，不上传数据库，不重启远端服务。

## 召回与精筛

### 范围约束

- 时间：`2026-01-16 00:00:00 <= ts < 专题执行时点`。
- 平台：原始平台字段严格等于 `Win`。
- 粒度：以原始 `feedback_id` 为最终去重键。

### 问题一：工具栏位置错乱

宽召回同时考虑工具栏、悬浮栏、浮窗、状态栏、输入法框等对象表达，以及错位、乱跑、位置重置、跨屏、多屏、左下角、右上角等现象表达。精筛只保留工具栏位置非预期变化、无法固定或跨屏定位错误的反馈；主动询问如何调整位置但未描述异常的反馈不纳入。

### 问题二：游戏全屏不隐藏

宽召回同时考虑游戏名称或游戏场景，以及全屏、隐藏失败、持续置顶、遮挡、误触等表达。精筛只保留游戏全屏期间工具栏未隐藏的问题；纯视频、直播、浏览器或其他非游戏全屏反馈不纳入。

### 上下文和判定

- 宽召回只用于降低漏召回，不直接决定是否导出。
- 对候选反馈附加同一 `user_vid` 前后 30 分钟内的用户消息作为判定上下文。
- 专题精筛输出 `matched`、`issue_type`、简短理由和置信度；只有明确命中上述两类之一的记录进入 Excel。
- 一条反馈同时命中两类时按主要诉求选择一个问题类型，避免重复行。
- 通用 L1/L2/severity 标签不参与准入判断。

## Excel 交付物

工作簿包含一个 `反馈清单` 工作表，每行对应一条去重后的原始反馈，按问题类型分组并按反馈时间倒序排列。字段为：

- 问题类型
- 反馈时间
- 反馈原文
- 对应会话链接
- Win 版本
- 设备信息
- 反馈 ID

会话链接优先使用原始 `external_chat_url`；缺失时根据 `channel`、`service_vid` 和 `user_vid` 生成。无法生成有效链接的记录保留在质量检查结果中，但不静默输出空链接。

工作表启用筛选、冻结表头、自动换行和合适列宽，使用统一专业字体。清单不需要公式。

## 质量检查

交付前执行以下检查：

1. 历史补拉日期无缺口，专题快照覆盖完整目标区间。
2. 所有导出行的 `platform` 均为 `Win`，时间均在目标区间内。
3. `feedback_id` 唯一，无重复导出。
4. 每行都有非空原文、问题类型和可用会话链接。
5. 逐类抽查明确命中样本和边界样本，确认位置调整咨询、视频全屏等相邻问题已排除。
6. 复核两类最终数量、最早时间、最晚时间，并与候选筛选记录一致。
7. 重新打开生成的 `.xlsx`，验证工作表名称、列顺序、链接和格式可用。

## 验收标准

- Excel 覆盖 2026-01-16 至执行时点的完整 Win 原始反馈数据。
- 清单只包含工具栏位置错乱或游戏全屏不隐藏两类问题。
- 每条反馈包含可读原文和可点击的对应会话链接。
- 数据库补拉、专题精筛和 Excel 生成均在本地专题副本完成，远端生产数据和服务未被修改。
