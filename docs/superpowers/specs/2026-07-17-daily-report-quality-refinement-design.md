# 日报质量改进设计

日期：2026-07-17

## 1. 背景

2026-07-14 日报洞察信号层已经完成从 404 个原子主题到 30 条 shortlist、再到最多 5 条正文的全局终选。现有结果具备去重会话统计、历史基线和原反馈链接，已经可以用于人工 Review，但仍存在三类质量问题：

1. 报告层合并主题后重新统计了会话数，却沿用原子候选趋势的交集，导致聚合频次与趋势结论不一致。
2. 全局终选偏向高频存量问题和需求，证据明确的新问题可能同时从正文和观察区消失。
3. 最终报告混排所有类型，不能直接回答“今天有什么新增或上升问题、持续问题、需求机会和高价值单条”。

本轮只改进日报洞察信号层和产物渲染，不重跑会话抽取、问题单元、原子主题或局部洞察模型。

## 2. 目标

1. 所有报告趋势均由报告层合并后的去重会话序列确定性计算。
2. 正文继续采用全局比较，最多 5 条，可以为空，不设置类型配额。
3. 全局模型同时选择少量观察信号，避免有价值的新问题静默消失。
4. 报告顶部直接回答四类业务问题，并明确没有确认结论的类别。
5. 报告正文使用面向产品同学的中文表达，保留平台、版本、证据边界和原反馈链接。
6. 复用 2026-07-14 已有局部产物完成验证，只新增一次全局终选调用。

## 3. 不做范围

- 不改变原子主题和稳定主题记忆。
- 不重跑 171 个局部洞察模型任务。
- 不设计周报门槛。
- 不引入统一综合重要性分数。
- 不为正文中的 Bug、需求或高价值单条设置最低数量。
- 不读取图片或视频内容。
- 不把日报判断反向写入事实标签。

## 4. 聚合趋势规范化

### 4.1 计算时点

`enrich_insights_with_evidence` 完成以下聚合后，再计算最终趋势：

- 合并来源候选的当日 `conversation_id` 并去重；
- 按日期合并历史 `conversation_id` 并去重；
- 得到统一的 `today_conversation_count` 和 `baseline_daily_counts`。

最终报告不得继续使用各来源候选 `allowed_trend_claims` 的交集作为合并洞察趋势。

### 4.2 规范趋势

沿用现有确定性阈值生成允许趋势集合，再按以下优先顺序选择唯一的 `canonical_trend_claim`：

1. `new_signal`：历史七日均为零且当日出现；
2. `reappeared`：历史存在、最近两日为零、当日再次出现；
3. `rising`：满足现有绝对增量和相对增幅阈值；
4. `persistent`：历史至少两个自然日出现；
5. `repeated`：当日至少两个去重会话；
6. `none`：不满足以上条件。

该顺序优先表达当天信息增量。例如重新出现同时满足数值上升时，仍使用“重新出现”；长期持续且当日明显抬升时使用“上升”。

### 4.3 结构化字段

报告层洞察新增或覆盖以下字段：

- `source_trend_claim`：局部模型原始判断，仅供审计；
- `allowed_aggregate_trend_claims`：聚合频次支持的趋势集合；
- `trend_claim`：规范化后的唯一最终趋势。

shortlist、全局终选和报告只消费最终 `trend_claim`。局部原始判断不得覆盖聚合后的确定性结果。

趋势规范化后同步校验 Bug 类型：

- 局部 `new_bug` 的聚合趋势不再是 `new_signal` 时，规范为 `rising_or_repeated_bug`；
- 局部 `rising_or_repeated_bug` 的聚合趋势是 `new_signal` 时，规范为 `new_bug`；
- `demand_opportunity` 和 `high_value_single` 保持原类型，不因时间趋势自动改类。

原始 `signal_type` 保存在 `source_signal_type`，供 Review 审计。

## 5. 全局双层终选

### 5.1 正文

`selected_insights` 保持现有语义：

- 从完整 shortlist 横向比较；
- 最多 5 条，可以为 0 条；
- 不设置类型配额；
- 不能选择需要人工复核、缺少来源链接或与已选项来源重叠的洞察；
- 频次只是证据之一，不能自动等价于重要性。

模型需要特别比较“长期高频但当天缺少增量的存量需求”和“频次较低但证据具体的新问题”。正文仍由价值比较决定，不强制纳入新问题。

### 5.2 观察项

全局终选同一次调用新增 `watch_insights`，最多 5 条，可以为空。每项包含：

```json
{
  "insight_id": "shortlist 中的洞察 ID",
  "rank": 1,
  "watch_reason": "为什么尚未进入正文，以及继续观察什么",
  "editorial_note": "必要的证据限制"
}
```

观察项必须：

- 来自 shortlist，且未进入正文；
- 不带 `needs_human_review`，至少有一个来源链接；
- 与正文及其他观察项不存在来源候选重叠；
- 优先保留证据明确但仍需更多频次、更多天数据或元数据确认的新问题、重新出现问题和高价值单条；
- 说明真实观察原因，不得只写“未进入今日重点”。

若 shortlist 中存在 `new_signal` 或 `reappeared`，全局输出还必须提供 `novelty_tradeoff`，说明哪些当天增量信号进入正文、哪些保留观察，以及其余信号未展示的总体原因。该字段不决定修复优先级，只记录日报取舍。

显式证据与平台、版本等元数据冲突时，以证据内容限定问题边界，并在 `editorial_note` 中暴露冲突。存在明显冲突的候选优先进入观察项，不直接把矛盾元数据写成正文事实。

全量局部 `observe` 仍保留在 Review 工作簿和检索产物中，但不再由渲染层按“类型 + 置信度”截取前五条作为日报观察区。

### 5.3 失败处理

双层终选共用一次模型调用和一次 schema 校验。正文或观察项存在非法 ID、重复来源、无链接或错误排名时，整次结果进入有限重试。最终仍失败则保持 `selection_blocked`，不使用规则排序自动生成正文。

## 6. 报告结构

### 6.1 今日结论

报告顶部新增固定摘要，分别回答：

1. 新增或上升问题；
2. 持续问题；
3. 需求机会；
4. 高价值单条。

摘要以正文为主要结论，同时说明观察区是否存在相应待验证信号。某类没有正文结论时，明确写“正文未确认”；不能因为没有入选正文就制造“当天不存在该类候选”的印象。

摘要同时确定性统计 shortlist 中各类候选数量。存在新增或重新出现候选但未被正文、观察区展示时，报告给出未展示数量并引导至 Review 工作簿，不逐条扩张日报篇幅。

### 6.2 今日重点

正文继续按全局排名展示，最多 5 条。每条包含：

- 中文类型和中文趋势；
- 核心判断；
- 为什么值得今日关注；
- 当日去重会话数；
- 带日期的七日基线或便于扫描的基线摘要；
- 已知平台和版本；
- 全局终选提供的证据边界；
- 最多 3 条代表反馈链接。

不得展示 `persistent`、`none` 等内部英文枚举，也不得使用“产品影响优先级”“修复优先级”等越过日报关注判断边界的措辞。

### 6.3 新增信号观察

展示全局终选的 `watch_insights`，而不是机械截取局部观察池。每条包含标题、中文类型/趋势、判断、观察原因、频次和原反馈链接。

### 6.4 媒体附录

保持现有独立附录。文本足以识别问题时正常参与候选；只有媒体存在而文本不足时进入附录，不与正文频次混用。

### 6.5 运行说明

日报只展示：

- 数据日；
- 历史基线范围；
- 按去重会话统计的口径；
- 当前为离线实验草稿。

模型渠道调用分布继续保存在 `run_summary.json`，不进入面向产品同学的日报正文。

## 7. 数据流

```text
已有局部洞察
  -> 聚合来源候选与去重会话
  -> 确定性规范化趋势
  -> 重建 shortlist
  -> 一次全局模型调用选择正文和观察项
  -> schema 与证据边界校验
  -> 生成今日结论、正文、观察区和媒体附录
  -> 输出 Markdown、Review 工作簿和 run_summary
```

## 8. 兼容与产物

- `global_selection.json` 新增 `watch_insights` 和 `novelty_tradeoff`，保留原有 `selected_insights` 和 `selection_summary`。
- 旧的全局选择结果缺少 `watch_insights` 时按空列表读取，避免解析历史产物失败。
- Review 工作簿的 `report_layer` 使用 `main`、`watch`、`manual_review`；完整未选洞察仍可保留在单独工作表或现有候选表中。
- `run_summary.json` 增加 `watch_insights` 数量，不删除模型渠道统计。

## 9. 2026-07-14 验证

本轮复用以下已有产物：

- `candidate_recall.jsonl`；
- `insight_decisions.jsonl`；
- 原始问题单元和来源链接；
- 媒体附录。

重新执行：

1. 洞察证据聚合与趋势规范化；
2. shortlist 构建；
3. 一次全局双层终选；
4. Markdown 和 XLSX 产物生成。

人工 Review 时重点比较：

- iOS 输入法切换问题是否根据聚合数据正确表达为“上升”；
- 多语言需求是否表达为“持续”，且说明键盘为主要诉求、语音输入为次要证据；
- “打字无输出再次出现”等新信息是否至少出现在正文或观察区；
- 正文是否仍然没有为了类型齐全而凑数；
- CAD 闪退等元数据冲突案例是否进入观察项并明确展示证据边界。

## 10. 测试与验收

### 10.1 单元测试

- 合并后频次支持 `rising` 时，最终趋势覆盖局部 `persistent`；
- 合并了新原子候选但整体历史持续时，最终趋势为 `persistent` 而不是 `none`；
- `new_signal`、`reappeared`、`rising` 的优先顺序符合本设计；
- 趋势规范化后，`new_bug` 与 `rising_or_repeated_bug` 能同步修正且保留原始类型；
- 正文和观察项 ID 合法、排名连续、互不重复且来源不重叠；
- 历史 `global_selection.json` 缺少 `watch_insights` 时兼容为空；
- 渲染结果包含四类今日结论、中文趋势、观察原因和证据边界；
- 渲染结果不包含模型渠道分布和内部趋势枚举。

### 10.2 验收标准

- 正文最多 5 条，观察项最多 5 条，两者均允许为空；
- 所有趋势都能由合并后的逐日去重会话统计复现；
- 报告明确回答四类业务问题；
- 所有正文和观察项都至少有一个有效原反馈链接；
- 新增或重新出现信号未进正文时，至少由观察项、`novelty_tradeoff` 和确定性候选数量共同留下可审计的取舍记录；
- 7 月 14 日新版报告经人工 Review 后，不再出现“结构化趋势与标题冲突”或“强新信号从可读报告完全消失”的阻断问题。

## 11. 后续路径

7 月 14 日验证通过后，使用相同代码和参数回放 2026-07-08 至 2026-07-13，检查：

- 正文与观察项的跨日稳定性；
- 同一持续问题的重复疲劳；
- 新问题进入观察区后如何升级或退出；
- 日报门槛是否需要与后续周报门槛进一步分离。
