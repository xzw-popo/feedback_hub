## 这个项目在解决什么问题

微信输入法每天收到 1500~2000 条用户反馈，目前没有人力逐条看。这个项目要做的事情是：**用规则 + 大模型对反馈自动分类打标，然后把有价值的信息分发给对的人**。

具体服务两类用户：

| 服务对象 | 给他们什么 | 期望效果 |
|---|---|---|
| **产品** | 前端看板，聚焦"建议""咨询"类反馈 | 观察用户真实需求，辅助判断迭代方向 |
| **开发** | 企微群每日推送 Top Bug | 快速感知高频/严重 Bug，缩短响应时间 |

## 已完成的工作

### 1. 数据采集 → 入库 → 会话聚合

- 对接微信 OpenAPI，增量拉取用户反馈
- SQLite 本地存储，已回灌 30 天历史数据（~44MB）
- 自动将多条消息聚合为"会话"（同一用户 30 分钟内的反馈归为一组）

### 2. 打标流水线（逻辑层）

- 分类体系设计完成：
  - L1（一级标签）：Bug / 建议 / 咨询 / 情绪 / 无效 / 待定
  - L2（二级标签）：输入核心 / 语音 / 皮肤 / 性能 等 12 类
  - 严重度：P0（不可用）~ P3（建议/无效）
- 规则引擎（关键词/正则优先匹配）+ LLM 兜底的双层打标逻辑已编码完成
- **但**：规则和提示词均为初版，LLM 调用通道尚未稳定（见下方"进行中"）

### 3. 前端 Dashboard（基本可用）

- 三个页面已开发完成：概览（KPI + 图表）/ 反馈列表（筛选 + 分页）/ 反馈详情
- 技术栈：Vue 3 + TypeScript + Element Plus + ECharts
- 能跑、能看数据，但体验和展示逻辑还需优化

### 4. 每日 Top Bug 推送（逻辑层）

- 推送编排完成：Bug 关键词分组 → 签名聚合去重 → 多维打分排序 → 格式化为 Markdown
- 企微 Webhook 调用代码就绪
- **但**：企微机器人尚未创建，通道未打通

### 5. 查询 API

- 5 个 RESTful 端点，供 Dashboard 和 CSV 导出使用，功能完整
