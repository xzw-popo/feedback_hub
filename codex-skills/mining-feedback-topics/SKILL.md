# Mining Feedback Topics

Use the bundled client; do not query source databases or vector tools directly. The packaged internal default applies; `FEEDBACK_TOPIC_API_URL` is an optional override and `FEEDBACK_TOPIC_API_TOKEN` is unused for the current internal deployment. For plans, do not claim results. Preserve user-named objects and behaviors as required inclusion conditions; exclude unrequested adjacent topics.

A blocked pre-run response contains four slots: proposed inclusion, proposed exclusion, one material scope question, and the service or configuration blocker. Treat an explicit relative time range as supplied scope; resolve whole-day relative ranges from `available_through`. Never use the Agent's system or local current time. With no boundaries, default to the most recent 14 days from `default_time_days=14`; never default to all history. When exactly one boundary is supplied or timezone is unknowable, ask: “What start time, end time, and timezone should this run use?”

1. **Capabilities.** Run [topic_backend_client.py](scripts/topic_backend_client.py) with `capabilities`. Require exact caller-AI v2 ownership, schema versions, formats, statuses, read-only flags, limits, the canonical platform contract, and ready `source_freshness.available_through`.
2. **Validate.** Read the [topic spec](references/topic-spec.md). Use `unit: feedback`. Populate each hard-scope field only with values explicit in the current request; leave every other hard-scope field empty. Preserve platform intent; `prepare-spec` resolves canonical spelling. Default to `mode: standard`; use `mode: exhaustive` only for explicit all, complete, or exhaustive intent. Six months alone is not exhaustive. Run `prepare-spec --spec TOPIC_SPEC_PATH --output PREPARED_SPEC_PATH`; add `--window-days DAYS` for whole days. [validate_topic_spec.py](scripts/validate_topic_spec.py) anchors absent times, canonicalizes platforms, and writes separately. Unsupported or ambiguous platforms block creation; repair scope.
3. **Create.** Run `create-run --spec PREPARED_SPEC_PATH`. Reuse its ID; never replace it.
4. **Inspect.** Read the [backend contract](references/backend-contract.md). Poll `get-run RUN_ID` until `classification_ready`; inspect funnel counts, cutoff, vector watermark, and unresolved failures. Use `resume RUN_ID` only for a recoverable pre-classification Run on its original ID. Classification states are caller-owned.
5. **Classify.** Read the [decision policy](references/review-policy.md). Fetch `candidate-page RUN_ID --output PAGE --offset OFFSET --limit 20`. Independently decide every item from the boundary, `item.text`, and `context_items`. Write one `{item_id,label,reason,evidence}` per item; run `apply-classifications RUN_ID --page PAGE --file DECISIONS`. Repair rejected items only with `--repair`. Follow `next_offset` and `next_pending_offset`. Never ask the backend to classify.
6. **Verify.** At `pending_decision_count=0` and `verification_ready`, run `verify RUN_ID`. Require exact candidate coverage, source-grounded evidence, valid links, and zero data/index gaps.
7. **Export.** Run `export RUN_ID --format xlsx|jsonl`; always `download RUN_ID ARTIFACT --output FILE` for `feedback_list.xlsx` as byte-exact `OFFICIAL_XLSX`. Validate it with [ensure_feedback_hyperlinks.py](scripts/ensure_feedback_hyperlinks.py) `--check`. A transformed workbook is supplementary: retain `Feedback ID` and its link column, then repair to distinct `VERIFIED_XLSX`. Every presented `.xlsx` must pass this gate; a plain-text link or failed workbook must not be delivered.
8. **Deliver.** Present `OFFICIAL_XLSX` as the first file, labeled “backend official Excel”; it must not be replaced and must not be hidden. List validated supplements. Report official failures; never substitute a generated workbook. Provide run ID, cutoff, counts, and limitations. Copy only these five backend-returned fields: `mode`, `result_scope`, `matched_total`, `returned_feedback`, `possibly_more_matches`. Preserve `result_scope=reviewed` or `result_scope=representative`; never invent a result_scope value. Representative is not complete. No formal labels. Candidate tuning remains backend-owned.
